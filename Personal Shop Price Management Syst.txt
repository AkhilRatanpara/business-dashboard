Personal Shop Price Management System
1. Project Overview
Build a private, mobile-first web application for managing product/item prices for my submersible pump repair shop.
The application is primarily for my personal use. I receive price updates for many different items from suppliers and need one centralized place to:

Store all items
Organize items into categories
Search items very quickly
Add new items
Edit existing items
Maintain three different prices for every item
Automatically calculate profit
Maintain a complete price-change history
View recently changed prices
View a dashboard with useful statistics
Work properly on mobile phones and desktop/laptop
Persist all data in a real PostgreSQL database
Keep data available when navigating between pages
Deploy the application on Vercel

IMPORTANT:
This must NOT be a static website where data disappears after refresh.
All important data must be stored in PostgreSQL.
When I update an item on /items, the updated data must immediately be available on /price-history, /dashboard, search results, category pages, and item details.

15. Automatic Profit Calculation
Do NOT store calculated profit as the main source of truth.
Calculate it from prices.
Retailer profit:
retailerPrice - costPrice
Customer profit:
customerPrice - costPrice
Example:
Cost:
₹90
Retailer:
₹120
Customer:
₹150
Results:
Retailer profit = ₹30
Customer profit = ₹60

16. Profit Percentage
Display profit percentage consistently.
Prefer showing markup percentage:
Retailer markup:
((retailerPrice - costPrice) / costPrice) × 100
Customer markup:
((customerPrice - costPrice) / costPrice) × 100
Example:
Cost = ₹100
Retailer = ₹130
Retailer markup = 30%
Customer = ₹160
Customer markup = 60%
Clearly label this as "Markup %" so it is not confused with profit margin.
Handle cost price = 0 safely.

20. History Must Never Be Overwritten
IMPORTANT:
When an item's price changes, do NOT simply overwrite the previous price and lose the old value.
The current item table stores the current prices.
The price_history table stores every change.
Example:

1 Aug → ₹90
10 Aug → ₹95
18 Aug → ₹100
27 Aug → ₹105

67. Final Development Instruction
Build this as a production-quality personal business application, not a demo.
Do not use fake/static data after the database is connected.
Do not implement the price history only in frontend state.
Do not use localStorage as the main database.
Do not require a Vercel redeployment when prices change.
All persistent business data must live in PostgreSQL.
Use database transactions for price updates and history creation.
Use proper validation, authentication, error handling, loading states and responsive UI.
The final application should feel like a simple personal "Price Book + Price History" system designed specifically for a submersible pump repair shop.
The primary goal is:
Open → Search item → See 3 prices → See profit → Quickly update price → Automatically preserve complete history.
